# AGENTS.md

Taskly = project/task manager. Two **independent** apps in one repo; there is no root
manifest, workspace, CI, or shared script. Run commands from inside `backend/` or
`frontend/`.

- `backend/` — NestJS 11 + Prisma 7 + PostgreSQL REST API (WebSockets not implemented)
- `frontend/` — React 19 + Vite 8 + TanStack Router/Query SPA

Both use **Bun** (`bun.lock`); do not use npm/pnpm/yarn.

## Setup (fresh clone)

Backend, from `backend/`:

1. Enter the Nix shell with `nix develop` (or `direnv allow` if a local `.envrc` exists;
   it is gitignored). The flake is x86_64-linux only; it provides `nodejs_24`, `bun`, and
   `prisma-engines_7`, and sets `PRISMA_SCHEMA_ENGINE_BINARY`.
2. `bun install`
3. `cp .env.example .env` and fix it: `.env.example` will **not** boot — `DATABASE_URL`
   is blank, both JWT secrets need ≥32 chars, and `MAIL_FROM` must be an email (or omit
   it). The compose DB URL is `postgresql://postgres:root@localhost:5432/db_taskly`.
4. `bunx prisma generate` — the generated client is gitignored, so this is required on
   every fresh clone and after editing `schema.prisma`.
5. `docker compose up -d` — Postgres 15 on `:5432`; the file is `compose.yml`, not
   `docker-compose.yml`.
6. `bunx prisma migrate dev`
7. `bun run start:dev`

Frontend, from `frontend/`: `bun install`, copy `.env.example` to `.env` and fill all
three `VITE_*` vars (`src/config/env.ts` throws at import if any is blank), then
`bun run dev`.

## Backend commands

```
bun run test                  # unit tests (no DB)
bun run test:e2e              # e2e (needs Postgres + .env)
bun run lint                  # ESLint with --fix
bun run format                # Prettier --write
bun run build && bun run start:prod
```

- **Unit tests live under `test/unit/**`**, NOT colocated in `src/`. Jest `testMatch` is
  `**/test/unit/**/*.spec.ts`. Run one file: `bunx jest test/unit/auth/auth.service.spec.ts`.
- E2E uses `test/jest-e2e.json`, `testMatch **/test/**/*.e2e-spec.ts`, and boots the real
  `AppModule` (`test/e2e/setup/app.ts`, helpers in `test/e2e/helpers/`). Run one:
  `bunx jest --config ./test/jest-e2e.json test/e2e/auth.e2e-spec.ts`.
- E2E uses `.env`'s `DATABASE_URL` directly (there is no separate test DB) and does not
  clean up; it creates random-suffixed users/workspaces, so reruns are safe but data
  accumulates. Don't point it at a DB you care about. Auth tests wait ~1.1s between token
  operations because JWT `iat` is second-granular.

## Prisma 7 quirks

- Generated client output is `src/generated/prisma` (**gitignored**). Import from
  `src/generated/prisma/client`, `.../enums`, `.../models` — never `@prisma/client`
  (except inside generated code).
- `moduleFormat = "cjs"` in the generator.
- The datasource has **no `url` in `schema.prisma`**; it comes from `prisma.config.ts`
  (`env('DATABASE_URL')`) for CLI and from `PrismaService` via `@prisma/adapter-pg`.
- `PrismaModule` is `@Global()` and provides `PrismaService`, which connects with a
  `PrismaPg` adapter.

## Backend architecture conventions

- Feature module per domain under `src/modules/<name>/`. Default flow is
  `controller → service → repository`, but `tasks`, `comments`, and `checklists` services
  also inject `PrismaService` directly — don't "fix" that blindly.
- Sub-domains are nested sub-modules: `tasks/{checklists,comments,attachments}`,
  `workspaces/{members,invitations}`.
- Cross-cutting Nest infra in `src/common/` (guards, decorators, interfaces);
  framework-free enums/utils in `src/shared/`.
- Roles live in `workspace-role.enum.ts` / `board-role.enum.ts`, enforced by
  `workspace-roles.guard.ts` / `board-roles.guard.ts`.
- Mail is event-driven: emit `MAIL_EVENTS`; `mail.listener.ts` sends asynchronously and
  skips delivery with a warning when SMTP is not configured. The due-soon notification
  scheduler runs hourly.

## Frontend quirks

- **TanStack Router file-based routing**: routes in `src/routes/`
  (`_public/`, `_authenticated/`). `src/routeTree.gen.ts` is **generated by the Vite
  plugin** — do not hand-edit. After adding/renaming a route, run `bun run dev` once:
  `bun run build` runs `tsc -b` before Vite regenerates the tree.
- Path alias `@/* → ./src/*` (vite + tsconfig).
- `bun run build` runs `tsc -b` (the only typecheck) then Vite; it enforces
  `noUnusedLocals`, `noUnusedParameters`, and `erasableSyntaxOnly`. `bun run lint` =
  `eslint .` (no autofix).
- `src/config/env.ts` throws at import if `VITE_API_URL`, `VITE_ACCESS_TOKEN_KEY`, or
  `VITE_REFRESH_TOKEN_KEY` are missing.
- `src/lib/api/client.ts` attaches the access token and retries a request once on `401`;
  URLs containing `/auth/` are excluded from refresh, and concurrent refreshes share one
  promise.
- Tailwind is v4: theme tokens live in `@theme` in `src/index.css`; there is no
  `tailwind.config.js`.
- No frontend test runner is configured yet (F6 pending); don't assume Vitest/Testing
  Library is available.

## Style

- Backend Prettier: single quotes, trailing commas. Frontend has no Prettier config and
  existing code uses double quotes.
